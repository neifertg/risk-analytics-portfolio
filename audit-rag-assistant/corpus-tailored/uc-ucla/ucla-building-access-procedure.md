# UCLA Procedure 825.1: Building Entrance Keying, Electronic Access, and Control

## What This Document Is

This is UCLA's own real, currently-effective procedure (effective April
11, 2025, superseding a June 2023 version), issued by the Assistant Vice
Chancellor for Facilities Management and available at
[adminpolicies.ucla.edu/pdf/825-1.pdf](https://www.adminpolicies.ucla.edu/pdf/825-1.pdf).
It's the single clearest example in this tailored corpus of what
"tailoring" actually buys: this demo's synthetic
[IT User Access Review](../../corpus/it-user-access-review.md) procedure
describes *how to test* access provisioning and deprovisioning in the
abstract; this document is a specific, real institution's actual written
process for exactly that risk area, in its own words, with its own named
roles and systems.

## Governance Structure: Building Coordinators

Each UCLA building has a designated Building Entrance Key Control
Coordinator and/or Building Coordinator, responsible for reviewing and
approving departmental requests for keys and BruinCard access, performing
periodic reviews of departments' own recordkeeping, and maintaining lists
of who holds building access. This decentralized-but-defined-role
structure is a real answer to a question the generic corpus's access
review procedure poses generically ("who authorizes access changes") —
here it's a named position with named responsibilities, not a generic
"appropriate approver."

## The Physical-to-Electronic Access Transition

As of this procedure, UCLA continues transitioning from physical keys to
BruinCard electronic reader access for most buildings, with at least two
entrances per building expected to carry BruinCard readers. Once a
building has transitioned, BruinCard becomes the *only* authorized
electronic building-access system on campus for after-hours entry — a
real, current example of an institution mid-migration between two access
technologies, a scenario the generic corpus's synthetic procedures don't
address because they're written as if one access model already exists
cleanly.

## Key Issuance, Retrieval, and Loss Reporting

The procedure specifies a full request-to-retrieval lifecycle: departments
submit a Facilities Service Request for key duplication or rekeying,
approved by the Building Coordinator and forwarded to Facilities
Management's Hardware Shop; BruinCard access requests route through the
Building Coordinator to the BruinCard Center; and — the deprovisioning
half this corpus's generic access-review procedure treats as the highest-
risk gap — departments must obtain keys back from terminating or
transferring staff and notify the Building Coordinator and BruinCard
Center of the change. If keys or a BruinCard can't be recovered, or an
individual refuses to return them, the procedure requires notifying UCPD
(campus police) directly, not just an internal access system update — a
real escalation path a synthetic procedure wouldn't invent on its own.

## After-Hours Lockout Access

A separate section governs what happens when an authorized individual is
locked out after hours: they call Facilities Management's Trouble Desk,
which verifies the requester against UCLA's official Space Inventory
database before granting access — access is denied by default unless the
requester is a listed occupant of that specific space, with escalation to
the department head or Building Coordinator if verification fails. This
is a concrete, real control against exactly the "someone claims
authorization, no independent check happens" failure mode the generic
corpus's access-review procedures describe only as a risk to test for.
